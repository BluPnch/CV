# ЛР3: дополнительный вариант SUPIR для Kaggle

Этот вариант использует предобученную SUPIR на базе SDXL и изменяет её RestoreEDMSampler для восстановления только в бинарной области. Исходная работа в `LW3` сохранена. Результатов SUPIR пока нет: их нужно получить запуском notebook на CUDA GPU. Установка и полный инференс на Kaggle пока не проверены; локально проверяются контракты маски и подготовка опытов.

## Метод

SUPIR использует испорченный вход как условие восстановления. В отличие от SD 1.5 из первого варианта, здесь используется штатный EDM SUPIR, а не DDIM. После каждого шага с уровнем шума `sigma_next`:

```text
z_next = M * z_proposal + (1-M) * (z_input + sigma_next * epsilon_fixed)
```

Это аддитивные координаты EDM, поэтому формула отличается от DDPM/DDIM. `z_input` — обычное VAE-кодирование испорченного входа, не чистого эталона и не результата предварительного удаления шума. Начальное состояние тоже ограничивается маской. `s_churn=0`, один фиксированный шум на траекторию; при конечном sigma=0 снаружи возвращается `z_input`. После декодирования исходные RGB-пиксели вне маски копируются точно. При нулевой маске модель не вызывается. Цветовая коррекция после диффузии выключена.

Маска — H×W, значения 0/1. Размеры дополняются справа и снизу до кратности 64, затем обрезаются; скрытого увеличения короткой стороны до 1024 нет. Вход для SUPIR уже увеличен bicubic после деградации ×4. Базовый размер опорной фотографии ограничен длинной стороной 512 для сопоставимости с LW3; для проверки 1024 укажите новый каталог результатов и `--max-side 1024`. Это отдельный эксперимент, его метрики нельзя напрямую сравнивать с 512.

Для экономии памяти VAE, текстовые энкодеры и диффузионная сеть загружаются на одну GPU последовательно, используется FP16 для диффузии и FP32 для VAE с обработкой плитками. LLaVA не загружается: описание фиксировано вручную. Две T4 не превращаются автоматически в одну GPU с удвоенной памятью; используется `cuda:0`. Возможность запуска зависит также от RAM и разрешения, отсутствие OOM не гарантируется. Сначала запускайте короткий протокол.

## Протокол исследований

Короткий запуск: Gaussian σ=15, baseline/zero/one/mixed, seed=42. Полный `--full`: девять деградаций (bicubic; Gaussian 5/15/30; Poisson peak 30/10; salt-and-pepper 1%/5%; blur 1.2 + Gaussian 5 + JPEG 60), семь форм маски для Gaussian 15, повтор seed=123 и control=0.8/1/1.2 для one/mixed. Это 48 условий на фотографию. `control` — сила условия SUPIR, она не эквивалентна `strength` SD 1.5. Смена seed изменяет и входной, и диффузионный шум. Форма и площадь масок меняются совместно.

Шум добавляется на LR до bicubic; размытие выполняется перед уменьшением. Это собственные контролируемые деградации, а не готовый DIV2K unknown/RealESRGAN. Метрики относятся к уменьшенной опорной фотографии. PSNR считается по RGB полного кадра; LPIPS меньше — лучше, CLIP-IQA больше — лучше. CSV дополнительно содержит PSNR ROI, площадь маски, число шагов и максимальное изменение вне ROI. Результаты сохраняются без потерь в PNG. Сравнивать с LW3 следует при одинаковых фотографиях, разрешении, входном шуме и масках.

`evaluate.py` запускается отдельным процессом, по умолчанию на CPU, чтобы метрики не конкурировали с SUPIR за видеопамять. Он создаёт реальные таблицы и графики, но не формулирует заранее вывод о превосходстве модели. Для отчёта после запуска нужно описать наблюдаемые улучшения/ухудшения, используя полученные метрики и изображения.

## Как загрузить и запустить в Kaggle

1. Из корня проекта соберите архив:

   ```powershell
   .\LW3\.venv\Scripts\python.exe LW3_2/package.py
   ```

2. Откройте [Kaggle Datasets](https://www.kaggle.com/datasets), нажмите **New Dataset**, загрузите `LW3_2_kaggle.zip`, задайте имя, например `lw3-supir-lab`. Выберите **Private**. Архив содержит три фотографии из `input`, код и notebook. Веса загружать вручную не нужно.
3. Откройте [Kaggle Code](https://www.kaggle.com/code), создайте **New Notebook**. Через **File → Import Notebook** импортируйте локальный `LW3_2/kaggle_supir.ipynb` (названия пунктов могут немного отличаться).
4. Справа через **Add Input / Add Data** подключите созданный dataset. В настройках notebook включите **Internet** и **Accelerator → GPU**, например T4, если доступна. Если GPU недоступна, проверьте ограничения/подтверждение аккаунта в интерфейсе Kaggle.
5. Запускайте ячейки сверху вниз. Первая найдёт загруженный проект и скопирует его в `/kaggle/working/LW3_2`, поскольку `/kaggle/input` предназначен для чтения. Далее создаётся отдельная среда `/kaggle/working/supir_lab/venv`; системный PyTorch Kaggle не заменяется.
6. Установка и загрузка весов требуют времени, свободного диска и RAM. SDXL и SUPIR — примерно 12 ГБ только для двух основных файлов, дополнительно скачиваются CLIP и библиотеки. По умолчанию используется SUPIR-v0F; веса взяты с указанного ниже стороннего зеркала, SDXL — из репозитория Stability AI. Ревизии и SHA-256 фиксируются в `weights.json`.
7. Сначала выполните тесты, подготовку и короткий запуск. После него посмотрите сравнения. Для полного исследования выполните отдельную ячейку `--full`; она пишет в другую папку. Не запускайте одновременно два процесса SUPIR.
8. Последняя ячейка создаёт `/kaggle/working/LW3_2_results.zip` с изображениями, CSV, отчётом и сведениями о среде. Скачайте его из панели файлов/Output. Для сохранения результатов версии notebook используйте **Save Version → Save & Run All** с нужными ячейками. Не включайте полную серию, пока не пройден короткий запуск.

Среда Kaggle Linux: команды `.venv\Scripts\python.exe` там не используются. В notebook все запуски выполняются отдельным Python через `subprocess`, поэтому ядро Kaggle перезапускать для установки пакетов не нужно. При смене конфигурации выбирайте новый `--output`; повторный запуск с теми же параметрами переиспользует проверенные PNG. После прерывания сессии восстановите папку результатов из скачанного архива и повторите настройку среды.

Обработка одной фотографии из ячейки notebook после установки (изображение и маска должны иметь одинаковый размер):

```python
run('restore.py', '/kaggle/working/input.png', '/kaggle/working/mask.png',
    '/kaggle/working/restored.png', '--root', ROOT)
```

В PNG-маске белый (255) разрешает обработку, чёрный (0) сохраняет вход. Произвольный большой вход в этой команде автоматически не уменьшается; сначала проверьте небольшой размер.
