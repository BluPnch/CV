# Основной код ЛР3: подробное объяснение

Этот документ объясняет [sr_inpainting.py](sr_inpainting.py): загрузку модели, обработку одной картинки с маской и сохранение результата. Исследования, перебор параметров, метрики и графики здесь не рассматриваются.

## 1. Что получает программа и что возвращает

На вход подаются изображение и маска такого же размера. **Маска** — таблица чисел: `1` разрешает изменить пиксель, `0` требует сохранить его. Выбранный участок называется **ROI — Region of Interest, область интереса**.

Программа возвращает изображение того же размера. Внутри маски находятся пиксели, полученные после обработки нейросетью, снаружи — точная копия входных пикселей.

Используется готовая **Stable Diffusion 1.5**. Обучения нет: программа не меняет веса, то есть внутренние параметры нейросети. Она меняет способ пошагового получения результата — **сэмплинг**.

Важная особенность: основной файл сам не уменьшает изображение в четыре раза и не увеличивает его через bicubic. Он получает уже подготовленный вход. В лабораторной такой вход создаёт функция `degrade` из `experiment.py`: уменьшает картинку, при необходимости добавляет искажения и увеличивает обратно. Именно этот увеличенный, но размытый или зашумлённый вход передаётся в `restore`.

## 2. Какие компоненты используются

| Компонент | Простое объяснение |
|---|---|
| NumPy, `np` | Работа с картинкой и маской как с массивами чисел |
| Pillow, `Image` | Открытие, преобразование и сохранение изображений |
| PyTorch, `torch` | Вычисления нейросети на процессоре или видеокарте |
| Diffusers | Готовые компоненты диффузионной модели |
| Энкодер VAE | Переводит изображение в компактный набор чисел |
| Латент | Этот компактный набор чисел, с которым работает диффузия |
| U-Net | Оценивает шум в латенте на текущем шаге |
| DDIMScheduler | По оценке шума рассчитывает следующий латент |
| Декодер VAE | Превращает итоговый латент обратно в картинку |
| Текстовый энкодер | Переводит текстовое описание в числа для U-Net |

VAE расшифровывается как **Variational Autoencoder — вариационный автоэнкодер**. Для чтения кода достаточно понимать его две операции: изображение → латент и латент → изображение. Обратное преобразование приблизительное, поэтому само по себе не сохраняет исходные пиксели точно.

## 3. Проверка маски: `validate_mask`

```python
mask = np.asarray(mask)
if mask.shape != (size[1], size[0]) or not np.isin(mask, [0, 1]).all():
    raise ValueError('Mask must be a binary H×W array matching the input image')
return mask.astype(bool)
```

`np.asarray` представляет маску как массив. У Pillow размер записан как `(ширина, высота)`, а у массива изображения первые измерения идут как `(высота, ширина)`. Поэтому сравниваем с `(size[1], size[0])`.

`np.isin(mask, [0, 1])` проверяет каждый элемент: равен ли он нулю или единице. `.all()` требует, чтобы проверку прошли все элементы. Если размеры неправильные или есть другие значения, `raise ValueError` останавливает обработку с сообщением об ошибке.

`astype(bool)` переводит значения в логический вид: `0 → False`, `1 → True`. Это удобно для выбора пикселей.

## 4. Точное сохранение фона: `composite`

```python
mask = validate_mask(mask, source.size)
return Image.fromarray(
    np.where(mask[..., None], np.asarray(generated), np.asarray(source))
    .astype('uint8')
)
```

`source` — входная картинка, `generated` — картинка после нейросети. `np.where` выбирает:

- где маска равна `True`, взять значение из `generated`;
- где маска равна `False`, взять значение из `source`.

У RGB-картинки три цветовых канала: красный, зелёный и синий. Её форма — `H × W × 3`. У маски форма `H × W`. Запись `mask[..., None]` добавляет измерение и даёт `H × W × 1`, чтобы одна и та же маска применялась ко всем трём каналам.

`uint8` — целые числа от 0 до 255, обычный формат цветовых значений. `Image.fromarray` превращает массив обратно в объект картинки Pillow.

**Именно эта функция гарантирует точное сохранение пикселей вне ROI.** Если на входе вне маски был шум, он тоже сохранится.

## 5. Смешивание скрытых представлений: `blend_latents`

```python
return mask * proposal + (1 - mask) * reference
```

Функция действует уже не на RGB-пиксели, а на латенты:

- `proposal` — новый вариант, предложенный диффузионным алгоритмом;
- `reference` — представление входа с шумом нужного уровня;
- `mask` — маска, уменьшенная до размеров латента.

Если маска равна `1`, выражение превращается в `proposal`. Если равна `0` — в `reference`. Таким образом, после каждого шага вне маски возвращается соответствующее представление входа.

Это центральное изменение сэмплинга. Одной финальной вставки готового фрагмента было бы недостаточно для выполнения требования изменить сам процесс сэмплинга.

## 6. Создание модели: `MaskedDiffusion.__init__`

### 6.1. Выбор устройства

```python
self.device = ('cuda' if torch.cuda.is_available() else 'cpu') if device == 'auto' else device
cuda = self.device.startswith('cuda')
```

`cuda` означает вычисления на видеокарте NVIDIA, `cpu` — на процессоре. В режиме `auto` программа выбирает CUDA, если PyTorch видит доступную видеокарту. Иначе использует процессор. Можно передать устройство явно.

### 6.2. Выбор точности чисел

```python
self.offload = cuda and 'GTX 16' in torch.cuda.get_device_name(self.device)
dtype = torch.float16 if cuda and not self.offload else torch.float32
```

`float16` и `float32` — способы хранения дробных чисел с 16 и 32 битами на число. FP16 требует меньше памяти, но имеет меньший диапазон и точность.

В этой реализации для карт с `GTX 16` в названии выбирается FP32: при прежнем запуске на GTX 1660 Ti в FP16 возникали некорректные числовые значения. На CPU также используется FP32. На остальных CUDA-картах по этой логике выбирается FP16.

### 6.3. Загрузка готовых весов

```python
self.pipe = StableDiffusionImg2ImgPipeline.from_pretrained(model, torch_dtype=dtype)
self.pipe.vae.to(dtype=torch.float32)
```

`from_pretrained` загружает уже обученную модель из локальной папки или репозитория моделей. `Img2Img` означает **image-to-image**: обработка существующего изображения.

`self.pipe` хранит компоненты системы. Стандартный вызов всего конвейера здесь не используется: далее программа сама вызывает энкодер, U-Net, планировщик и декодер, чтобы вставить обработку маски внутрь цикла.

VAE отдельно переводится в FP32 для устойчивого кодирования и декодирования.

### 6.4. Планировщик и экономия памяти

```python
self.pipe.scheduler = DDIMScheduler.from_config(self.pipe.scheduler.config)
self.pipe.enable_attention_slicing()
```

**Планировщик, scheduler**, задаёт уровни шума и формулу перехода между ними. Здесь используется DDIM, созданный с настройками исходного планировщика.

`attention_slicing` делит часть вычислений механизма внимания на порции. Это уменьшает пиковое потребление памяти и может замедлять обработку.

```python
if self.offload:
    self.pipe.model_cpu_offload_seq += '->safety_checker'
    self.pipe.enable_model_cpu_offload(device=self.device)
else:
    self.pipe.to(self.device)
```

**CPU offload** означает перенос компонентов между оперативной памятью и видеопамятью по мере необходимости. Это помогает работать с ограниченной видеопамятью; все компоненты не требуется постоянно держать на GPU одновременно. В последовательность переноса включена и штатная проверка результата `safety_checker`.

В другой ветви модель просто переносится на выбранное устройство.

## 7. Параметры восстановления: `restore`

```python
def restore(self, image, mask, *,
            prompt='a detailed sharp natural photograph',
            negative_prompt='blurry, low quality, artifacts',
            steps=30, strength=0.35, guidance=5.0, seed=42):
```

| Параметр | Значение |
|---|---|
| `image` | Уже подготовленная входная картинка |
| `mask` | Бинарная маска её размера |
| `prompt` | Текстовое описание желаемого результата |
| `negative_prompt` | Описание нежелательных свойств |
| `steps` | Число шагов полного расписания DDIM |
| `strength` | Определяет используемую часть расписания и начальный уровень шума |
| `guidance` | Сила текстового направления при объединении двух оценок шума |
| `seed` | Начальное число генератора случайного шума |

Звёздочка `*` в объявлении функции означает, что последующие аргументы передаются по имени: например, `strength=0.35`.

Больший `strength` обычно допускает более сильное изменение входа. Больший `guidance` усиливает влияние текстовых условий, но не гарантирует лучшего восстановления.

## 8. Подготовка картинки и маски

### 8.1. Проверки и пустая маска

```python
image = image.convert('RGB')
mask = validate_mask(mask, image.size)
if steps < 1 or not 0 < strength <= 1 or int(steps * strength) < 1:
    raise ValueError('Require steps >= 1 and 1/steps <= strength <= 1')
if not mask.any():
    return image.copy()
```

`convert('RGB')` приводит картинку к трём цветовым каналам. Проверка параметров требует хотя бы один реальный шаг обработки.

`mask.any()` отвечает, есть ли хотя бы одна единица. Если нет, менять нечего, поэтому функция возвращает копию входа и не вызывает нейросети. Если объект `MaskedDiffusion` уже был создан, веса к этому моменту уже загружены; в командном запуске есть отдельная проверка, позволяющая избежать даже загрузки.

### 8.2. Дополнение размера до кратности 8

```python
p = self.pipe
w, h = image.size
pad = ((0, (-h) % 8), (0, (-w) % 8))
pixels = np.pad(np.asarray(image), (*pad, (0, 0)), mode='edge')
padded_mask = np.pad(mask, pad, mode='edge')
```

У VAE пространственный размер латента в восемь раз меньше размера картинки. Для удобной работы ширина и высота дополняются до кратности 8.

Например, при ширине 410 добавляются 6 столбцов справа: получается 416. `(-410) % 8 = 6`. Если размер уже кратен 8, добавляется 0 пикселей.

`mode='edge'` заполняет добавленную область копиями крайнего столбца или строки. Так же дополняется маска. Для цветового измерения `(0, 0)` означает, что каналы не дополняются.

Изображение не растягивается: координаты исходной маски сохраняются. В конце добавленные края будут отрезаны.

## 9. Перевод изображения в латент

```python
with torch.inference_mode():
    tensor = p.image_processor.preprocess(Image.fromarray(pixels)).to(self.device, p.vae.dtype)
    original = p.vae.encode(tensor).latent_dist.mode() * p.vae.config.scaling_factor
    original = original.to(getattr(p.unet, 'dtype', original.dtype))
```

`torch.inference_mode()` отключает служебные вычисления для обучения. Здесь не вычисляются градиенты и не обновляются веса.

**Тензор** — многомерный массив чисел PyTorch. `preprocess` преобразует картинку в формат модели: добавляет измерение количества картинок, переставляет цветовые каналы и нормирует значения. Для данного конвейера RGB-значения переводятся из 0…255 в диапазон примерно −1…1.

Пример размеров:

```text
Картинка NumPy:       512 × 384 × 3
Тензор для VAE:       1 × 3 × 512 × 384
Латент SD 1.5:        1 × 4 × 64 × 48
                     ↑   ↑    ↑    ↑
                  число канал высота ширина
                 картинок
```

Четыре канала латента — внутренние признаки, а не цвета RGBA.

`encode` получает распределение возможных скрытых представлений. `.mode()` выбирает его моду, то есть наиболее вероятное значение, без случайной выборки. `scaling_factor` приводит масштаб чисел к ожидаемому U-Net. Это не увеличение ширины или высоты изображения.

Переменная `original` содержит **латент входной картинки**, включая её искажения. Эталонная фотография сюда не передаётся.

```python
if not torch.isfinite(original).all():
    raise FloatingPointError('Non-finite VAE encoding')
```

`isfinite` проверяет отсутствие `NaN` — некорректных чисел — и бесконечностей. При ошибке программа останавливает обработку вместо сохранения испорченного результата.

## 10. Маска в размерах латента

```python
roi = torch.tensor(padded_mask.copy(), device=self.device, dtype=original.dtype)[None, None]
roi = F.interpolate(roi, size=original.shape[-2:], mode='nearest')
```

Маска переводится в тензор. `[None, None]` добавляет два измерения: число картинок и число каналов. Получается `1 × 1 × H × W`.

`original.shape[-2:]` берёт последние два размера латента — высоту и ширину. `interpolate` приводит маску к этим размерам. Метод `nearest`, ближайший сосед, сохраняет значения 0 и 1: промежуточных серых значений не возникает.

Например, `1 × 1 × 512 × 384` превращается в `1 × 1 × 64 × 48`. Одна маска применяется ко всем четырём каналам латента автоматически.

Ограничение: очень узкий или маленький участок может исчезнуть при уменьшении маски. Кроме того, одна позиция латента не соответствует строго изолированному блоку 8 × 8 пикселей: энкодер и декодер учитывают соседние области. Поэтому для точного сохранения фона нужна финальная функция `composite`.

## 11. Шум и выбор шагов

```python
generator = torch.Generator(device=self.device).manual_seed(seed)
noise = torch.randn(original.shape, generator=generator,
                    device=self.device, dtype=original.dtype)
```

Создаётся генератор случайных чисел с заданным `seed`. `randn` создаёт массив нормального шума той же формы, что и латент: среднее 0, дисперсия 1.

Это **внутренний шум диффузии**. Он отличается от шума, который мог быть заранее добавлен к RGB-картинке при подготовке входа.

Одинаковый `seed` позволяет повторять случайную последовательность в одинаковых условиях. Полное совпадение результата между разными устройствами и версиями библиотек этим не гарантируется.

```python
p.scheduler.set_timesteps(steps, device=self.device)
timesteps = p.scheduler.timesteps[steps - int(steps * strength):]
latents = p.scheduler.add_noise(original, noise, timesteps[:1])
```

Сначала строится полное расписание из `steps` уровней шума. Затем берётся его последняя часть:

```text
steps = 30
strength = 0.35
int(30 * 0.35) = 10
Начальная позиция среза: 30 - 10 = 20
Используются последние 10 шагов расписания.
```

`int` отбрасывает дробную часть. `timesteps[:1]` берёт первый выбранный уровень в виде массива из одного элемента. `add_noise` смешивает исходный латент с шумом на этом уровне. С этого состояния начинается уточнение.

## 12. Подготовка текстовых условий

```python
positive, negative = p.encode_prompt(prompt, self.device, 1, True, negative_prompt)
embeddings = torch.cat([negative, positive])
```

Текстовый энкодер преобразует два описания в наборы чисел — **эмбеддинги**. Положительный текст описывает желаемые свойства, отрицательный — нежелательные.

`torch.cat` соединяет их в один пакет, сначала отрицательное условие, затем положительное. Этот порядок важен: далее результаты U-Net разделяются в том же порядке.

## 13. Главный цикл: пошаговое уточнение с маской

```python
for index, timestep in enumerate(timesteps):
```

`index` — номер прохода цикла: 0, 1, 2 и так далее. `timestep` — соответствующий уровень шума из расписания. Это разные числа: десять проходов цикла не означают уровни шума от 0 до 9.

### 13.1. Две оценки шума за один вызов

```python
model_input = p.scheduler.scale_model_input(torch.cat([latents] * 2), timestep)
unconditional, conditional = p.unet(
    model_input, timestep, encoder_hidden_states=embeddings
).sample.chunk(2)
```

Текущий латент дублируется, чтобы обработать его сразу с двумя текстовыми условиями. Это один вызов U-Net, но пакет содержит два элемента.

`scale_model_input` подготавливает масштаб входа согласно выбранному планировщику. U-Net получает латенты, текущий уровень шума и текстовые признаки. Его выход здесь — **оценка шума**, а не готовая картинка.

`.sample` — имя поля результата U-Net; само название поля не означает случайную выборку. `.chunk(2)` разделяет пакет на две части:

- `unconditional` — оценка с отрицательным текстом;
- `conditional` — оценка с положительным текстом.

Название `unconditional` историческое: в данном коде эта ветвь получает отрицательное описание, поэтому буквально «совсем без текста» она не работает.

Далее обе оценки проверяются через `isfinite`.

### 13.2. Объединение оценок: CFG

```python
prediction = unconditional + guidance * (conditional - unconditional)
```

**CFG — Classifier-Free Guidance** — способ направить результат текстом с помощью разности двух оценок шума.

При `guidance=1` получается положительная оценка `conditional`. При `guidance=5` разность между положительной и отрицательной оценками усиливается в пять раз и прибавляется к отрицательной оценке. Это происходит с каждым числом тензора.

### 13.3. Расчёт следующего состояния

```python
proposal = p.scheduler.step(prediction, timestep, latents, eta=0).prev_sample
```

DDIM использует оценённый шум, текущий уровень и текущий латент, чтобы получить следующий, менее зашумлённый латент. `prev_sample` — поле с этим следующим состоянием при движении от большого шума к малому.

`eta=0` отключает дополнительный случайный шум в переходах DDIM. Начальный шум всё равно существует: он был создан перед циклом.

Пока `proposal` — предложение для всего изображения. Ограничение по маске применяется следующей операцией.

### 13.4. Восстановление области вне маски на каждом шаге

```python
reference = (
    p.scheduler.add_noise(original, noise, timesteps[index + 1:index + 2])
    if index + 1 < len(timesteps) else original
)
latents = blend_latents(proposal, reference, roi)
```

Для области вне маски готовится исходный латент с шумом **следующего** уровня. Шумовой массив `noise` тот же, что использовался в начале, а не новый случайный массив на каждом шаге.

Почему нужен следующий уровень: `proposal` уже перешёл к нему. Обе смешиваемые части должны соответствовать одному уровню шума.

На последнем шаге следующего уровня в списке нет. Тогда берётся `original` без дополнительного диффузионного шума. Слово «без шума» здесь относится к добавленному шуму диффузии: искажения входной фотографии в `original` остаются.

После смешивания:

```text
Внутри маски:  следующий латент от DDIM.
Вне маски:    латент входа с нужным уровнем шума.
```

Результат смешивания становится входом следующего прохода цикла. Поэтому маска влияет на весь процесс, а не только на финальное изображение. При этом U-Net вычисляется для всего кадра: небольшая ROI сама по себе не означает пропорционального ускорения.

## 14. Получение картинки из итогового латента

```python
decoded = p.vae.decode(
    (latents / p.vae.config.scaling_factor).to(p.vae.dtype),
    return_dict=False
)[0]
```

Ранее латент умножили на `scaling_factor`; перед декодером это масштабирование отменяется делением. `.to(p.vae.dtype)` приводит числа к точности VAE.

`decode` превращает скрытое представление в RGB-изображение в форме тензора. `return_dict=False` просит вернуть результат как кортеж; `[0]` извлекает из него тензор изображения. Затем снова проверяется отсутствие некорректных чисел.

```python
decoded, flags = p.run_safety_checker(decoded, self.device, embeddings.dtype)
generated = p.image_processor.postprocess(decoded, output_type='pil')[0].crop((0, 0, w, h))
```

Запускается штатная проверка содержимого модели. `flags` сообщает, был ли результат отклонён. `postprocess` переводит тензор в обычное изображение Pillow. `[0]` выбирает единственную картинку из пакета, а `crop` обрезает добавленные справа и снизу края, возвращая исходные ширину и высоту.

```python
if getattr(self, 'offload', False):
    p.maybe_free_model_hooks()
if flags is not None and any(flags):
    raise SafetyCheckRejected('Model safety checker rejected the generated image')
```

При использовании offload выполняется предусмотренное конвейером завершение работы механизмов переноса компонентов. Если проверка отклонила результат, выбрасывается специальное исключение `SafetyCheckRejected`. Оно объявлено в начале файла как разновидность `RuntimeError`, чтобы вызывающий код мог отличить отказ проверки от других ошибок.

В командном запуске это исключение не перехватывается: программа завершится до сохранения результата.

```python
return composite(image, generated, mask)
```

Финальная операция вставляет обработанный фрагмент в исходный вход. Она обеспечивает точное сохранение фона, которого нельзя добиться только ограничением латентов из-за приблизительной работы VAE.

## 15. Командный запуск: `main`

`argparse` читает параметры командной строки. Три обязательных аргумента:

```text
image  — путь к входной картинке;
mask   — путь к маске;
output — путь для результата.
```

Дополнительно доступны `--model`, `--device`, `--steps`, `--strength`, `--seed`, `--prompt`. Параметры `guidance` и `negative_prompt` есть у метода `restore`, но отдельными аргументами командной строки в этом файле не представлены.

### 15.1. Чтение маски из файла

```python
mask = np.load(args.mask, allow_pickle=False) if args.mask.suffix == '.npy' else np.asarray(
    Image.open(args.mask).convert('L')
)
```

Файл `.npy` хранит массив NumPy с нулями и единицами. `allow_pickle=False` запрещает загрузку сериализованных Python-объектов: здесь требуется только числовой массив.

Другой файл читается как изображение в оттенках серого: `L` означает один канал. Для такой маски разрешены только значения 0 и 255:

```python
if not np.isin(mask, [0, 255]).all():
    raise ValueError('PNG mask must contain only 0 and 255')
mask = mask // 255
```

Чёрный превращается в `0`, белый — в `1`. Серые края, которые могли появиться при сглаживании в графическом редакторе, вызовут ошибку. Лучше использовать PNG: сжатие JPEG может изменить значения маски.

### 15.2. Вызов восстановления и сохранение

```python
result = (
    MaskedDiffusion(args.model, args.device).restore(
        image, mask, steps=args.steps, strength=args.strength,
        seed=args.seed, prompt=args.prompt
    ) if mask.any() else image
)
args.output.parent.mkdir(parents=True, exist_ok=True)
result.save(args.output)
```

Если маска пустая, объект модели даже не создаётся. Иначе загружается модель и вызывается описанный выше метод `restore`.

`mkdir` создаёт папку результата вместе с недостающими родительскими папками. `exist_ok=True` разрешает использовать уже существующую папку.

Для точного сохранения фоновых пикселей результат нужно записывать в **PNG**. Сам массив после `composite` сохраняет фон точно, но последующее JPEG-сжатие способно изменить пиксели всего изображения.

В конце файла:

```python
if __name__ == '__main__':
    main()
```

Это запускает обработку аргументов только при непосредственном запуске файла. При импорте `MaskedDiffusion` из другого Python-файла `main` автоматически не вызывается.

## 16. Пример обработки одной картинки

Команды ниже выполняются из корня репозитория. Предполагается, что зависимости и локальные веса уже подготовлены. Вход `LW3/input_for_restore.png` должен существовать; здесь это условное имя уже увеличенной через bicubic картинки. Этот запуск не ограничивает её размер автоматически.

Сначала создаём маску с центральным прямоугольником:

```python
from PIL import Image
import numpy as np

image = Image.open('LW3/input_for_restore.png')
w, h = image.size
mask = np.zeros((h, w), dtype=np.uint8)
mask[h // 4:3 * h // 4, w // 4:3 * w // 4] = 1
np.save('LW3/roi.npy', mask)
```

Срез `h // 4:3 * h // 4` выбирает центральную половину строк, а аналогичный срез по ширине — центральную половину столбцов. Вместе получается прямоугольник примерно в четверть площади кадра. `//` — целочисленное деление.

Запускаем восстановление:

```powershell
.\LW3\.venv\Scripts\python.exe LW3/sr_inpainting.py LW3/input_for_restore.png LW3/roi.npy LW3/restored.png --model LW3/.cache/sd15 --device auto --steps 30 --strength 0.35 --seed 42
```

Здесь выполняется обработка одной картинки: без исследований, расчёта метрик и построения графиков.

## 17. Что важно уметь объяснить на защите

1. **Модель предобученная.** Веса загружаются, обучение не проводится.
2. **Основная обработка идёт в латенте.** Энкодер переводит вход в компактные числа, декодер возвращает изображение.
3. **U-Net предсказывает шум.** DDIM по этой оценке рассчитывает следующий латент.
4. **Маска применяется внутри каждого шага.** Снаружи ROI возвращается зашумлённое представление входа на соответствующем уровне.
5. **В конце фон копируется из входной картинки.** Это гарантирует точное совпадение вне ROI в возвращаемом изображении.
6. **Сохраняется ухудшенный вход, а не эталон.** Эталон основному алгоритму неизвестен.
7. **Улучшение не гарантировано.** SD 1.5 может создавать правдоподобные, но неверные детали; маска ограничивает разрешённые изменения, а не обеспечивает их качество.
